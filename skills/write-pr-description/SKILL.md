# Write a PR Description

## Goal
Produce a PR description a reviewer can understand in under a minute.

## Checklist
1. Summarize WHAT changed in one or two sentences.
2. Explain WHY — the problem or motivation behind the change.
3. List the key changes as short bullets (group by area if large).
4. Note how it was tested (commands run, scenarios covered).
5. Call out risks, breaking changes, or follow-ups explicitly.
6. Link related issues. Keep it factual — no hype.

## Anti-patterns
- Never write a vague title like "fixes" or "update".
- Never claim it was tested if it was not.
- Never hide breaking changes in the body.
